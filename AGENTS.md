Selected optional features: none.

If `PRODUCT_BRIEF.md` contains unresolved `TODO(REQUIRED)` fields, do not invent product direction. Foundation maintenance, tooling, tests, and brief-independent portability work may continue. Product behavior waits for the owner decisions.

## Prime Directive

Deliver the narrowest real production slice through durable boundaries. Do not create a disposable implementation that must be replaced to support another selected platform.

## Simplicity And Dependencies

- The baseline stack is C++20, CMake, Python's standard library, SDL3, SDL_GPU, and offline HLSL compilation through SDL_shadercross.
- Do not add a library because it is familiar or convenient. First record the capability, why existing code cannot own it simply, exact pin, licence, platform behavior, binary cost, update owner, and replacement tests.
- No entity-component framework, physics engine, scripting runtime, networking stack, logging framework, formatting library, image middleware, audio middleware, service SDK, or profiler is assumed.
- Keep optional functionality absent until the product needs it. Prefer a focused product-owned value contract over a general framework.
- Generated code, native projects, dependencies, cooked data, and shader binaries live under ignored build or external directories and are never hand-edited authorities.

## Binding Boundaries

- SDL types stay in the executable composition root, renderer, platform adapters, and SDL-backed implementations.
- Product logic and reusable UI contracts do not import SDL, GPU, filesystem, network, or platform APIs.
- Input is expressed as semantic actions before product behavior consumes it.
- Lifecycle, display, storage, assets, audio, accessibility, and optional product services have focused owners; there is no global service locator.
- Renderer code consumes presentation data and never owns product state.
- Product runtime packaging is allowlisted. Source assets, captures, fixtures, editors, credentials, and unlicensed material do not ship.
- Platform preprocessor branches are restricted to narrow adapters and build integration. Do not scatter them through product rules.
- Do not invent console SDK APIs. NDA-bound adapters and certification material belong in authorized private profile code.
- When `deterministic-authority` is selected, all gameplay mutations follow its intent, validation, ordered execution, replay, and hash rules. Without that profile, do not impose those rules unless the product brief adopts them.

## Verification And Memory

Use `python3 tools/project.py verify` as the aggregate repository gate and run focused tests while iterating. A passing host build proves only that host. Never convert missing device, signing, store, or certification evidence into a generic pass.

After a platform smoke/package qualification, run `python3 tools/project.py evidence`, include its GPU smoke log when applicable, and preserve the resulting `build/evidence` artifact with the CI run. This records exact tools, SDKs, compilers, dependency heads, host-tool hashes, packages, and backend output without committing disposable evidence to source.

Every substantial pass updates `docs/AI_DEVELOPMENT_LOG.md` newest-first with scope, decisions, changed owners, verification, caveats, and next action. Durable trade-offs go in `docs/TECHNICAL_DECISIONS.md` or a focused ADR.

Never weaken or delete a failing gate to produce a green report. Fix the mechanism or record a genuine external evidence gap.
